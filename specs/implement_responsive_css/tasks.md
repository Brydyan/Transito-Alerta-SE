# Lista de Tareas para Implementación de Estilos CSS Responsivos y Estandarización Visual

Este plan de tareas describe los pasos secuenciales y verificables para implementar la responsividad en dispositivos móviles, solucionar problemas de alturas, adaptar opciones del dashboard, armonizar modales y migrar tablas a componentes estándar en el frontend.

- [x] T1 — Estandarización de modales y bordes en estilos centrales ([components.css](file:///frontend/styles/components.css)). Actualizar `.premium-modal-content` y estilos generales de modal para asegurar `border-radius: var(--radius-xl) !important;` y añadir un borde visible, armonioso con la paleta actual (`border: 1px solid var(--border-color) !important;`). Cubre: R7, R8, R9.
- [x] T2 — Revisión y aplicación de clases estandarizadas a modales en las vistas del frontend (incluyendo [kanban-index.component.html](file:///frontend/js/pages/instituciones/components/kanban/kanban-index.component.html), [incidencia-form.component.html](file:///frontend/js/pages/incidencias/components/lobby/form/incidencia-form.component.html), [institucion-form.component.html](file:///frontend/js/pages/instituciones/components/form/institucion-form.component.html), [permission-form.component.html](file:///frontend/js/pages/permissions/components/form/permission-form.component.html), [role-form.component.html](file:///frontend/js/pages/role/component/form/role-form.component.html), y otros modales identificados). Inspeccionar los archivos HTML que declaran `.modal-content`, remover clases conflictivas como `border-0` que ocultan el borde, y asegurar que implementen la clase centralizada `.premium-modal-content`. Cubre: R7, R8, R9.
- [x] T3 — Ajuste de responsividad en el módulo de estado individual de incidencias ([estado-individual-incidencia-index.component.html](file:///frontend/js/pages/incidencias/components/estado-individual-incidencia/estado-individual-incidencia-index.component.html) y [estado-individual-incidencia-index.component.js](file:///frontend/js/pages/incidencias/components/estado-individual-incidencia/estado-individual-incidencia-index.component.js)). Modificar las alturas rígidas y estilos en línea (`max-height`, `min-height` de `50vh`/`80vh`) en el panel de chat y ciclo de vida, reemplazándolos con clases de responsividad y flexbox de Bootstrap o media queries que eviten la expansión vertical descontrolada en pantallas pequeñas (`< 992px`). Cubre: R1, R2, R3, R4.
- [x] T4 — Pruebas unitarias de responsividad y estructura para estado individual de incidencias ([estado-individual-incidencia-index.component.test.js](file:///frontend/js/pages/incidencias/components/estado-individual-incidencia/estado-individual-incidencia-index.component.test.js)). Verificar mediante tests de Jest que el componente renderizado utiliza las clases responsivas adecuadas y que las tarjetas y contenedores de chat no tengan alturas rígidas o estilos conflictivos que generen desbordamiento en resoluciones móviles. Cubre: R1, R4.
- [x] T5 — Implementación de responsividad en botones de acceso rápido del dashboard ([dashboard.component.js](file:///frontend/js/pages/dashboard/components/dashboard-index/dashboard.component.js) y [dashboard-cards.css](file:///frontend/styles/dashboard-cards.css)). Actualizar el generador de HTML para `dashboardMenuContainer` en `loadMenuData()` aplicando clases de utilidad (`d-none d-sm-block`, `justify-content-center justify-content-sm-start`, etc.) o reglas de media query en CSS que muestren solo el icono centrado en resoluciones pequeñas (`< 576px`) y el icono con texto en resoluciones grandes. Cubre: R1, R2, R3, R5, R6.
- [x] T6 — Pruebas unitarias para el menú responsivo del dashboard ([dashboard.component.test.js](file:///frontend/js/pages/dashboard/components/dashboard-index/dashboard.component.test.js)). Agregar o actualizar tests en Jest para comprobar que la generación de las tarjetas del menú de acceso rápido asigna correctamente las clases responsivas para ocultar el texto en móviles y mostrarlo en escritorio. Cubre: R5, R6.
- [x] T7 — Estandarización de la tabla del módulo de Categorías con `<app-data-table>` ([categorias-index.component.html](file:///frontend/js/pages/categorias/components/index/categorias-index.component.html) y [categorias-index.component.js](file:///frontend/js/pages/categorias/components/index/categorias-index.component.js)). Reemplazar la tabla HTML manual `#tbl-categorias` en el template por `<app-data-table id="tbl-categorias-data" title="Listado de Categorías" empty-text="No se encontraron categorías de incidencias registradas."></app-data-table>`, y refactorizar `cargarCategorias()` en el JS para configurar columnas, acciones y datos a través de `.configure()` y `.items`. Cubre: R1, R3, R10.
- [x] T8 — Pruebas unitarias para la tabla estandarizada del módulo de Categorías ([categorias-index.component.test.js](file:///frontend/js/pages/categorias/components/index/categorias-index.component.test.js)). Actualizar los tests de Jest para verificar que el componente se inicializa adecuadamente con `<app-data-table>`, que llama al método `configure()` con la estructura de columnas esperada y que pasa correctamente el listado de categorías. Cubre: R10.
- [x] T9 — Ajustes generales de media queries y revisión en vistas para evitar overflow horizontal ([layout.css](file:///frontend/styles/layout.css) y [components.css](file:///frontend/styles/components.css)). Revisar y ajustar reglas CSS globales de layout para móviles (`max-width`, paddings, márgenes, tablas en contenedores `table-responsive`), asegurando una correcta visualización en celulares sin desbordamiento horizontal y en armonía con Bootstrap. Cubre: R1, R2, R3.
- [x] T10 — Verificación global de la suite de pruebas frontend y confirmación de trazabilidad. Ejecutar la suite de tests (`npm test` o el comando correspondiente en `./init.sh`) para asegurar que el 100% de las pruebas pasan sin regresiones en todos los componentes modificados y documentar la trazabilidad de los requerimientos R1-R10. Cubre: R1, R2, R3, R4, R5, R6, R7, R8, R9, R10.
