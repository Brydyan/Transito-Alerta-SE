## FIX-1 (blocks archive) — Make anonymous-incident creation truly transactional

**Problem**: `IncidentsRepository.create()` always writes via
`this.dataSource.query(...)`, never via a passed-in `EntityManager`. When
`IncidentsService.create()` calls it from inside
`this.dataSource.transaction(async (manager) => {...})`, the `incidents`
INSERT runs outside that transaction and commits immediately, regardless of
whether the subsequent `incident_reporters` INSERT (which correctly uses
`manager.query`) succeeds or fails.

**Files to change**:
- `backend/src/modules/incidents/incidents.repository.ts` — add an optional
  manager/query-runner parameter to `create()`, e.g.:
  ```ts
  async create(input: CreateIncidentInput, manager?: EntityManager): Promise<IncidentRow> {
    const runner = manager ?? this.dataSource;
    const rows: IncidentRow[] = await runner.query(`INSERT INTO incidents ... RETURNING ${SELECT_COLUMNS}`, [...]);
    return rows[0];
  }
  ```
  (Mirror the pattern already correct in `AuditService.record(input, manager?)`.)
- `backend/src/modules/incidents/incidents.service.ts:110-133` — pass the
  transaction's `manager` through to `incidentsRepository.create(...)` in the
  `isAnonymous` branch.

**Test that must pass** (add it — currently missing):
- A real-DB (e2e, Testcontainers) test: create an anonymous incident where
  the `incident_reporters` INSERT is forced to fail (e.g. by pre-inserting a
  conflicting row with the same `incident_id`, or by revoking insert
  privilege in a scoped test transaction), then assert
  `SELECT * FROM incidents WHERE id = $1` returns **zero rows**. The current
  unit test (`incidents.service.anonymous.spec.ts`, "B.6: … hace rollback")
  must be kept but is not sufficient proof by itself — it mocks
  `repo.create()` and cannot detect this class of bug.
