**Learned**:
- Always count a legacy seeder's actual array/loop contents programmatically before trusting an earlier design-time estimate in the same document — this is now the 3rd time in this change (after T7.7's "6 FKs" and T7.8's "create all 9 indexes") that an early audit number was off and only caught by re-deriving it from source at implementation time.
- `TestEnvironment.reset()`'s TRUNCATE list is itself evidence of which tables are "migration-planted fixtures" (geo_zones/roles/organizations, explicitly excluded) vs "mutable per-test state" (everything else, including `incident_categories`) — now that 0038 seeds `incident_categories`, it conceptually belongs in the first group, but changing `reset()`'s TRUNCATE list would require auditing every e2e file that inserts its own categories assuming a clean slate (found 3: `map-ui-support`, `t7-org-hierarchy-categories`, `t7-referential-integrity`, all of which insert AFTER `env.reset()` already ran, so no collision either way) — left `reset()` unchanged as the lower-risk option, tests needing the actual seed use `MigrationHarness` instead.
- A permission's `@RequirePermission` decorator being present in the code proves NOTHING about whether that permission is actually reachable — always grep the migrations for the literal `"ACTION resource"` string before assuming a guarded route works. Two independent instances of this exact class of bug found in this session alone (the notifications 403 that 0039 fixes, and the incident-images wrong-format strings from 0029 that are NOT fixed).
- `grep`-ing `roles.permissions` JSONB contents surfaces bugs unrelated to what you're testing for free — worth doing even when not required by the task, as a side effect of writing a thorough R20.2 assertion.
